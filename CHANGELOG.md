# Changelog

## Unreleased

- Added a "Minimum frame interval" slider to the main web scanner (0–1000ms, default 50ms), matching the interval control the playground and screen-capture monitor already expose. The main scanner previously hard-coded a 900ms scan interval (~1.1 FPS) with no way to change it; the default is now 50ms and the scan loop is a self-rescheduling timer that reads the slider live, so `0` means "max speed" (send the next frame as soon as the worker finishes the previous one). A `workerBusy` gate still prevents overlapping scans, so effective FPS is capped by whichever is larger — the chosen interval or the worker's per-frame inference time (visible as `total …ms` in the debug perf overlay).
- Added live "VU meter" readouts beneath the main web scanner's sharpness and match-score sliders. Each shows the current per-frame value as a fill bar with a marker at the chosen threshold and a numeric readout, so the thresholds can be set by eye like a mic-gate slider on a soundboard (mirroring the meter the playground already uses). The sharpness meter updates every frame; the match meter reads "—" when no card is in frame (no score to report). Display-only — both values already arrive on every scanner result message.
- Added a "Sharpness threshold" slider to the main web scanner's settings sheet. This exposes the corner detector's `minCornerConfidence` gate (the confidence required before a frame is treated as a well-framed card), which the scanner page previously had no UI for — matching the control the playground and screen-capture monitor already offer. The slider updates the running scanner worker live via a `config` message and persists to `localStorage` (range 0–0.2, default 0.02).
- The `?channel=testing` asset selector now works on all three deployed web pages — the playground (`applet_example`) and screen-capture monitor now honor it in addition to the main scanner. Channel resolution moved into a shared `examples/web_scanner/asset-channel.mjs` module (single source of truth) so the three static entry points can't drift; `?channel=testing` loads from `./testing/assets/` and stable/no-param loads from `./assets/`. The applet library and monitor now forward the resolved `assetBasePath` to the inference worker, and the monitor also reads its `bundle-metadata.json` from the selected channel root.
- Fixed the catalog loading readout "flashing" from a large figure (e.g. ~27 MB) to a small one (~4.2 MB) at the end of the download. The catalog is fetched as several independent assets (the float16 embeddings matrix plus the card/oracle ID lists) that now stream concurrently, and each fetch was writing its own `loaded / total` into the single shared "catalog" loading step — so whichever finished last (the small ID list) clobbered the note. The worker now aggregates the concurrent catalog sub-fetches into one combined `loaded / total` and drives the step's progress from the summed byte fraction.
- Sped up web scanner startup and fixed the loading screen appearing to hang "waiting for the catalog to download". The worker previously loaded assets strictly sequentially — download both models, compile both ort-web WASM sessions (several seconds with no progress feedback), and only *then* start downloading the large catalog. The big catalog transfer now kicks off up front alongside the model downloads so it overlaps the silent WASM session compilation instead of running after it, and the loading progress bar is now monotonic so the concurrent stages no longer make it jump backward. There were no artificial delays; the hang was serialized I/O plus a feedback gap during session compile.
- The web scanner manifest now publishes an `asset_bytes` map with the authoritative *uncompressed* size of every downloaded asset (both model files and the catalog), keyed by the same relative paths the scanner fetches. The download progress reader uses these sizes as the total, so the loading screen shows an accurate `loaded / total` even though GitHub Pages serves the assets gzip/br-compressed (whose `Content-Length` reports the smaller compressed size). Progress ratios are clamped to 100%, and when no size is known the overlay falls back to loaded-only progress.
- Fixed the web scanner loading screen showing a nonsensical "loaded / total" (e.g. `3.0 MB / 2.8 MB`) while fetching models and the catalog. The numbers were not switched — the progress reader accumulates *decompressed* bytes, but `Content-Length` reports the *compressed* transfer size when GitHub Pages serves the asset gzip/br-encoded, so the loaded figure overshot the total. The fetch helper now prefers the manifest's `asset_bytes` size, treats `Content-Length` as unknown whenever a `Content-Encoding` is present, and reports loaded-only progress in that case (and still emits a deterministic completion tick).
- Added the `fastweb-single` corner-detection family (EfficientViT-B0 global-token SimCC) to the bundled model registry snapshot, resolving to `fastweb-single-1.39` on both the `stable` and `testing` channels. `NeuralCornerDetector(family="fastweb-single")` loads and runs it with no code changes — input size and the sharpness output are detected from the ONNX model at load time.
- Model artifact downloads now use the direct Hugging Face `resolve` URL via `urllib.request`, matching the registry fetch and the GitHub Actions workflow. The `huggingface_hub` package is no longer required to download model weights (it remains an optional dependency for catalog resolution). Hugging Face requests now send a descriptive `User-Agent`, avoiding intermittent HTTP 403 responses that the default `Python-urllib` agent triggers from cloud/CI IP ranges.
- Default corner detection now uses Cornelius 2.12 from Hugging Face, superseding 1.221 with the new global-token SimCC detector. This keeps the rotated-card quality fix tracked in [issue #24](https://github.com/HanClinto/CollectorVision/issues/24), where soft-argmax averaging could place corners between competing peaks.
- The Python library and generated web scanner assets now share the same bundled `collector_vision/weights/cornelius.onnx` default, so web scanner refreshes will publish Cornelius 2.12 automatically.
