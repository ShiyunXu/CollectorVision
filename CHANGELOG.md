# Changelog

## Unreleased

- The web scanner manifest now publishes an `asset_bytes` map with the authoritative *uncompressed* size of every downloaded asset (both model files and the catalog), keyed by the same relative paths the scanner fetches. The download progress reader uses these sizes as the total, so the loading screen shows an accurate `loaded / total` even though GitHub Pages serves the assets gzip/br-compressed (whose `Content-Length` reports the smaller compressed size). Progress ratios are clamped to 100%, and when no size is known the overlay falls back to loaded-only progress.
- Fixed the web scanner loading screen showing a nonsensical "loaded / total" (e.g. `3.0 MB / 2.8 MB`) while fetching models and the catalog. The numbers were not switched — the progress reader accumulates *decompressed* bytes, but `Content-Length` reports the *compressed* transfer size when GitHub Pages serves the asset gzip/br-encoded, so the loaded figure overshot the total. The fetch helper now prefers the manifest's `asset_bytes` size, treats `Content-Length` as unknown whenever a `Content-Encoding` is present, and reports loaded-only progress in that case (and still emits a deterministic completion tick).
- Added the `fastweb-single` corner-detection family (EfficientViT-B0 global-token SimCC) to the bundled model registry snapshot, resolving to `fastweb-single-1.39` on both the `stable` and `testing` channels. `NeuralCornerDetector(family="fastweb-single")` loads and runs it with no code changes — input size and the sharpness output are detected from the ONNX model at load time.
- Model artifact downloads now use the direct Hugging Face `resolve` URL via `urllib.request`, matching the registry fetch and the GitHub Actions workflow. The `huggingface_hub` package is no longer required to download model weights (it remains an optional dependency for catalog resolution). Hugging Face requests now send a descriptive `User-Agent`, avoiding intermittent HTTP 403 responses that the default `Python-urllib` agent triggers from cloud/CI IP ranges.
- Default corner detection now uses Cornelius 2.12 from Hugging Face, superseding 1.221 with the new global-token SimCC detector. This keeps the rotated-card quality fix tracked in [issue #24](https://github.com/HanClinto/CollectorVision/issues/24), where soft-argmax averaging could place corners between competing peaks.
- The Python library and generated web scanner assets now share the same bundled `collector_vision/weights/cornelius.onnx` default, so web scanner refreshes will publish Cornelius 2.12 automatically.
